# Product Requirements Document (PRD)
## tgplaylistbot (VKMusicBot + Weather Platform)

### 1. Архитектура и Базовые принципы (Существующий функционал)
- **Zero Server Storage**: Треки скачиваются во временную директорию (`/tmp/musicbot`), отправляются в Telegram и сразу же удаляются. Файлы не сохраняются на сервере.
- **Технологический стек**:
  - Web App: FastAPI (дашборд погоды, панель администратора, будущие страницы для прохождения капчи).
  - Telegram Bot: aiogram 3.x.
  - База данных: SQLite (`aiosqlite` без тяжелых ORM).
- **Интеграции**: VK Music, Spotify, YouTube (поиск), OpenWeatherMap (погода), AcoustID (распознавание аудио).
- **Ограничения**: Максимальный размер файла для скачивания — 49 МБ.
- **Пользовательские настройки**: Качество звука, приоритет платформ при поиске, количество результатов на страницу (`/settings`).
- **Распознавание музыки**: Интеграция с AcoustID для определения трека и исполнителя по аудиосообщениям.
- **Удаление по реакциям**: Удаление трека из плейлиста, если большинство участников поставили дизлайк (👎).

### 2. Пользователи и Персонализация (Новый функционал)
- **Хранение данных**: Бот должен хранить данные о пользователях (как минимум ник).
- **Онбординг**: При добавлении нового пользователя в канал или группу, бот должен спрашивать, как к нему обращаться.
- **Обращение**: Бот должен обращаться к пользователю по сохраненному нику/имени.
- **Общение в ЛС**: Бот должен уметь отвечать пользователю в личные сообщения, при условии, что этот пользователь состоит с ботом в общих чатах.

### 3. Работа в Группах и Топиках (Новый функционал)
- **Авто-конвертация**: При добавлении в обычную группу бот должен автоматически преобразовывать её в группу с топиками (форум).
- **Единая точка входа ("Общий чат")**: Все принимаемые заявки (поиск музыки и т.д.) обрабатываются и выдают результат **исключительно в рамках топика "General" / "Общий чат"**.
- **Обработка Капчи (VK)**:
  - *Текстовая капча*: Бот присылает картинку капчи прямо в "Общий чат" и ждет, пока пользователь введет ответ текстом.
  - *Нетекстовая капча (ReCaptcha/SmartCaptcha и т.д.)*: Бот генерирует уникальную ссылку и отправляет её пользователю. Ссылка уводит пользователя на веб-страницу (FastAPI) для прохождения капчи.

### 4. Управление треками, Чистота и Жизненный цикл топиков (Новый функционал)
- **Очистка спама ("Общий чат")**:
  - Результаты поиска прилетают в "Общий чат".
  - Пользователь нажимает определенный эмодзи под нужным треком, подтверждая выбор ("получил, что хотел").
  - Сразу после нажатия трек перемещается в соответствующий топик (чат-комнату), привязанный к этому эмодзи.
  - Все следы поиска (сообщения от бота с вариантами) **удаляются** из "Общего чата", не оставляя спама.
- **Отмена действий (Undo)**:
  - Нужна команда или кнопка возврата состояния (Undo), если пользователь случайно выбрал не тот эмодзи.
  - При возврате состояния список найденных треков возвращается на прежнее место в "Общем чате", а трек убирается из целевого топика.
- **Именование топиков**:
  - Название нового топика состоит из: `[Эмодзи] + [Название раздела (если пользователь задал) ИЛИ Жанр первого добавленного туда трека (если название не задано)]`.
- **Авто-удаление топиков**:
  - Если в любом топике (кроме "Общего чата") не осталось ни одного сообщения/трека (например, все удалили через 👎 или перенесли), этот топик **должен автоматически удаляться/закрываться**. "Общий чат" удалять нельзя.

### 5. Голосования, Очистка и Глобальные Настройки (Обновление)
- **Глобальные настройки (Bot Settings)**: Должны настраиваться как через админ-панель сайта, так и через Telegram (`/settings` для админов).
  - `vote_threshold_pct`: Процент голосов от участников чата для принятия решения (по умолчанию 25%).
  - `vote_interval_sec`: Задержка перед обработкой реакции, чтобы избежать случайных нажатий (по умолчанию 60 сек).
  - `download_delay_sec`: Глобальная задержка между скачиваниями треков во избежание спам-блокировок API (по умолчанию 3 сек).
  - `msg_ttl_days`: Время жизни сообщений с результатами поиска до автоудаления, если никто не проголосовал (по умолчанию 7 дней).
  - `forward_mode`: Способ переноса трека в топик (Форвард или Отправка заново с тегом). По умолчанию - переотправка с хештегом `#id_пользователя` для удобного сбора своих треков.
- **Новый флоу выбора топика (Reactions)**:
  - Кнопки с эмодзи под результатами поиска убираются. Остается только кнопка "Скачать".
  - При нажатии "Скачать" бот отправляет аудиофайл в Общий чат. Сообщение с результатами поиска и исходный запрос (ссылка/текст) **остаются** в чате.
  - Пользователи ставят **встроенные реакции Telegram** на сообщение с аудиофайлом.
  - Если любая реакция (например, 🔥 или 👎) набирает нужный процент голосов (25%), бот ждет `vote_interval_sec` (чтобы убедиться, что реакцию не убрали).
  - После этого трек переносится в соответствующий топик (или удаляется при 👎), а **все исходные сообщения** (результаты поиска, аудиофайл в общем чате, исходный запрос пользователя) удаляются.
- **Отображение битрейта**: Исправлен баг, из-за которого битрейт треков отображался как "—" (прочерк).
